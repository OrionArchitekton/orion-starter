Default/continuity component pins, examples and dependency/installer/npm locks are preserved. Existing published archives remain immutable. The source/release destination is the existing `OrionArchitekton/orion-starter` repository. Proposed companion copy belongs in the existing `OrionArchitekton/danmercede.com` guide surface at `/guides/agent-development-evidence-handoff`. Existing relevant Works pages may link to that guide after its package works. No new repository, microsite, DNS record, PyPI release, agent adapter or runtime integration is included.

## Private acceptance packet

Bind one committed source tree to a deterministic exact-member ZIP, component/installer hashes, profile locks, archive inventory and a sanitized external release-verification asset. Replay the extracted profile with installed public packages and real disposable Git stores. Preserve named failures as well as passing controls. Map S1-S8 in the living spec to actual evidence, including uncertainty, contention, incomplete coverage, backup/readback and environment removal.

Re-run existing default/continuity native workflows on a separate disposable browser-capable target with their real prerequisites. A source/fixture check is supporting evidence only. An unavailable isolated target is a release-review blocker, never permission to use signed-in shared resources. Keep historical receipts labeled with their original scope.

Review current advisories, licenses/notices, privacy, exact install/guide fences and local guide rendering. No independent newcomer, untested platform, power-loss or vendor-native support claim is inferred. The owner accepts exact source/archive/copy bytes before publication. Routine private repairs do not authorize changed outward scope.

## Ordered outward actions after explicit approval

1. Recheck the accepted source/tree/archive/copy and protected review gates. Open the existing Starter repository's source PR; complete required CI and qualified human review without bypassing protections.
2. Verify the protected merge tree equals the accepted source tree. Tag and publish only the accepted ZIP, checksums and sanitized verification asset. Use a new version for corrections; never overwrite an earlier archive.
3. Download anonymously, verify exact bytes and replay the installed profile. Recheck the previous immutable archive.
4. Land the accepted guide/hub links through their source/human gates after the package is available. Only then update any specifically approved existing Works links.
5. Verify the actual canonical guide's own title, body, canonical, Article data, sitemap and links in production. A merged PR or origin 200 alone is insufficient.

No public action is authorized by this local plan. No account messaging, social distribution, schedules, access grants or adoption into any installed runtime is included.

## Rollback and monitoring

Use attended exact download, native mode/readback and route checks; create no timer. Roll back by choosing the previous immutable distribution/environment with its matching component backups. Quiesce selected sessions before native backup/restore. Removing this environment preserves retained data. Incorrect future copy can be reverted through protected source review; an incorrect release requires a visibly new corrective version. See the persisted operations runbook for unknown-effect handling.
